# Exact sparse-draft crossover protocol

## Question

Before attributing any P/D latency gain to overlap, establish whether the
same-model draft path is genuinely cheaper when it sees fewer **exact BF16 KV
pages**. This experiment contains no network pacing and no verifier. It answers
the compute question only; the live three-arm P/D experiment answers the
end-to-end question.

## Controlled execution

- Model: Llama-3.1-8B-Instruct, BF16, one exclusive H200.
- Context: 16K, 32K, 64K, and 131,008 tokens.
- Page size: 64 tokens.
- Visible exact-page fractions: 2%, 5%, 10%, 25%, 50%, and 100%.
- Primary proposal horizon: 8; gamma sweep 4/8/16/32 at 64K.
- Three warmups, then 30 selection repeats per fraction. A frozen confirmation
  point uses 100 new rounds in a fresh process and does not reuse selection
  measurements.
- Greedy fixed-length draft; EOS is ignored.

The prompt is block aligned and warmed into vLLM's local prefix cache. Every
timed request appends a different valid one-token seed. Therefore all complete
prompt pages must be cache hits while the seed itself remains a real query.
Any request which recomputes a prompt page invalidates the cell.

The primary control is 100% visibility in the **same PROGRESSIVE_KV engine**.
This pairs model, allocator, prefix-cache state, metadata path, and thermal
history. Fractions rotate and reverse across repeats. A separately loaded
ordinary FLASH_ATTN engine measures the overhead of the progressive metadata
path; its 100%-visible ratio must be at most 1.10 before system conclusions are
drawn.

## Physical sparsity gate

The production backend passes a compact physical block table to unchanged
FlashAttention. Publishable timed requests disable mechanism trace collection:
no page hashing or file I/O is allowed inside their latency interval. After all
timed requests finish, one prefix-cache-hit audit request per fraction records a
representative layer-zero row per draft step, containing candidate/visible page
counts, full/sparse sequence length, exact arrival ranges, and a SHA-256 digest
of the selected logical pages. Every fraction below 100% must remove at least
one page and reduce the sequence length; the 100% arm must retain every
candidate page. All audit request IDs and all draft positions must be present,
and finding any timed request in the trace invalidates the cell.

For every request, the aggregator also reports exact logical BF16 K/V payload
addressed: `sum(sparse_seq_len) x bytes_per_token_across_all_layers`. This is a
one-read algorithmic byte count, not a claim about physical DRAM transactions.
For kernel attribution, rerun a representative 2%/10%/100% cell with
`--emit-nvtx` under Nsight Systems and report `nvtx_gpu_proj_sum` plus
`nvtx_kern_sum`. Profiler-instrumented wall times are excluded from latency
tables. Nsight Compute DRAM-byte counters are required if available; otherwise
the paper must label the payload count as logical rather than measured HBM
traffic.

## Statistical decision

Within each repeat, subtract each sparse latency from the 100%-visible latency.
Report raw request rows, mean/median/P95, ratio of means, and a deterministic
10,000-sample paired bootstrap 95% confidence interval. The selection
hypothesis is supported at a context length only if an operating point at or
below 10% visibility has:

1. at least 1.10x full-model draft speedup over the same-engine 100% control;
2. paired saved-time confidence interval entirely above zero; and
3. progressive 100%-visible overhead no more than 1.10x ordinary FlashAttention.

This threshold is a method-selection rule, not a validity gate: a valid cell
which misses it is retained and reported as evidence against the cheap-draft
hypothesis. The crossover context—the first length satisfying all conditions—
feeds the P/D break-even surface without being retroactively changed.

## Artifacts

`experiments/benchmark_sparse_draft_crossover.py` emits raw progressive and
FlashAttention JSONL, request-attributed attention JSONL, `summary.json`,
`summary.md`, and `paper_table.csv`. The frozen queue is generated by
`experiments/build_sparse_draft_crossover_queue.py`; it also contains a
separate Nsight Systems job whose instrumented wall times are explicitly
non-publishable. Execute a frozen selection cell through
`experiments/run_sparse_draft_crossover_job.py`; it verifies the queue and
input hashes, rejects non-empty outputs, checks physical GPU exclusivity, and
records an execution manifest only after every expected artifact passes.
